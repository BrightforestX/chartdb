# Internationalization Guidelines

## Overview
ChartDB uses i18next for internationalization. Follow these guidelines to ensure proper localization support.

## Setup

ChartDB is configured with:
- **i18next**: Core internationalization framework
- **react-i18next**: React bindings
- **i18next-browser-languagedetector**: Auto-detect user language

## Translation Keys

### Key Naming Convention

Use dot notation with descriptive, hierarchical keys:

```typescript
// ✅ Good - Descriptive, hierarchical keys
{
    "common": {
        "button": {
            "save": "Save",
            "cancel": "Cancel",
            "delete": "Delete"
        },
        "validation": {
            "required": "This field is required",
            "email": "Invalid email address"
        }
    },
    "diagram": {
        "title": "Diagram",
        "create": "Create Diagram",
        "edit": "Edit Diagram",
        "delete": {
            "title": "Delete Diagram",
            "confirm": "Are you sure you want to delete this diagram?"
        }
    },
    "table": {
        "name": "Table Name",
        "addField": "Add Field",
        "fields": {
            "name": "Field Name",
            "type": "Field Type",
            "nullable": "Nullable"
        }
    }
}

// ❌ Bad - Flat, unclear keys
{
    "btn_save": "Save",
    "btn_cancel": "Cancel",
    "msg1": "This field is required",
    "title": "Title"
}
```

## Using Translations

### useTranslation Hook

```typescript
import { useTranslation } from 'react-i18next';

// ✅ Good - Basic usage
export const CreateButton: React.FC = () => {
    const { t } = useTranslation();

    return <button>{t('common.button.create')}</button>;
};

// ✅ Good - With namespace
export const DiagramForm: React.FC = () => {
    const { t } = useTranslation('diagram');

    return (
        <form>
            <h2>{t('create')}</h2>
            <button>{t('common:button.save')}</button>
        </form>
    );
};

// ✅ Good - Multiple namespaces
export const ComplexComponent: React.FC = () => {
    const { t } = useTranslation(['diagram', 'table', 'common']);

    return (
        <div>
            <h1>{t('diagram:title')}</h1>
            <p>{t('table:description')}</p>
            <button>{t('common:button.save')}</button>
        </div>
    );
};
```

### Interpolation

```typescript
// ✅ Good - Variable interpolation
// Translation: "Welcome, {{name}}!"
const { t } = useTranslation();
<h1>{t('common.welcome', { name: user.name })}</h1>

// ✅ Good - Pluralization
// Translation:
// {
//   "diagram": "{{count}} diagram",
//   "diagram_other": "{{count}} diagrams"
// }
<span>{t('diagram.count', { count: diagrams.length })}</span>

// ✅ Good - Complex interpolation
// Translation: "Created {{count}} tables in {{duration}} seconds"
<p>{t('table.created', { 
    count: tables.length, 
    duration: (Date.now() - startTime) / 1000 
})}</p>
```

### Formatting

```typescript
// ✅ Good - Date formatting
import { useTranslation } from 'react-i18next';

const { t, i18n } = useTranslation();

const formattedDate = new Intl.DateTimeFormat(i18n.language, {
    year: 'numeric',
    month: 'long',
    day: 'numeric',
}).format(date);

// ✅ Good - Number formatting
const formattedNumber = new Intl.NumberFormat(i18n.language).format(count);

// ✅ Good - Currency formatting
const formattedPrice = new Intl.NumberFormat(i18n.language, {
    style: 'currency',
    currency: 'USD',
}).format(price);
```

## Trans Component

Use Trans component for complex translations with HTML:

```typescript
import { Trans } from 'react-i18next';

// ✅ Good - Trans with components
// Translation: "Click <1>here</1> to learn more"
<Trans i18nKey="help.clickHere">
    Click <a href="/learn-more">here</a> to learn more
</Trans>

// ✅ Good - Trans with interpolation
// Translation: "Welcome back, <1>{{name}}</1>!"
<Trans i18nKey="common.welcomeBack" values={{ name: user.name }}>
    Welcome back, <strong>{{name}}</strong>!
</Trans>

// ✅ Good - Trans with complex HTML
// Translation: "We found <1>{{count}}</1> diagrams in <3>{{category}}</3>"
<Trans 
    i18nKey="diagram.searchResults" 
    values={{ count: results.length, category }}
>
    We found <strong>{{count}}</strong> diagrams in <em>{{category}}</em>
</Trans>
```

## Namespace Organization

```typescript
// ✅ Good - Load namespaces on demand
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

i18n
    .use(initReactI18next)
    .init({
        lng: 'en',
        fallbackLng: 'en',
        ns: ['common', 'diagram', 'table'],
        defaultNS: 'common',
        resources: {
            en: {
                common: enCommon,
                diagram: enDiagram,
                table: enTable,
            },
            es: {
                common: esCommon,
                diagram: esDiagram,
                table: esTable,
            },
        },
    });

// Usage - specify namespace
const { t } = useTranslation('diagram');
```

## Language Detection

```typescript
// ✅ Good - Auto-detect with fallback
import LanguageDetector from 'i18next-browser-languagedetector';

i18n
    .use(LanguageDetector)
    .use(initReactI18next)
    .init({
        fallbackLng: 'en',
        detection: {
            order: ['localStorage', 'navigator', 'htmlTag'],
            caches: ['localStorage'],
        },
    });
```

## Language Switcher

```typescript
// ✅ Good - Language switcher component
import { useTranslation } from 'react-i18next';

export const LanguageSwitcher: React.FC = () => {
    const { i18n } = useTranslation();

    const languages = [
        { code: 'en', label: 'English' },
        { code: 'es', label: 'Español' },
        { code: 'fr', label: 'Français' },
    ];

    return (
        <Select
            value={i18n.language}
            onValueChange={(lang) => i18n.changeLanguage(lang)}
        >
            {languages.map((lang) => (
                <SelectItem key={lang.code} value={lang.code}>
                    {lang.label}
                </SelectItem>
            ))}
        </Select>
    );
};
```

## RTL Support

### Detecting RTL Languages

```typescript
// ✅ Good - RTL support
import { useTranslation } from 'react-i18next';

export const App: React.FC = () => {
    const { i18n } = useTranslation();
    
    const isRTL = ['ar', 'he', 'fa'].includes(i18n.language);

    useEffect(() => {
        document.dir = isRTL ? 'rtl' : 'ltr';
    }, [isRTL]);

    return (
        <div className={isRTL ? 'rtl' : 'ltr'}>
            {/* App content */}
        </div>
    );
};

// ✅ Good - RTL-aware styles
<div className={cn(
    'flex items-center',
    isRTL ? 'flex-row-reverse' : 'flex-row'
)} />
```

## Pluralization

```typescript
// Translation file
{
    "diagram": {
        "count": "{{count}} diagram",
        "count_other": "{{count}} diagrams",
        "count_zero": "No diagrams"
    }
}

// Usage
const { t } = useTranslation();

// ✅ Good - Automatic pluralization
<span>{t('diagram.count', { count: 0 })}</span>  // "No diagrams"
<span>{t('diagram.count', { count: 1 })}</span>  // "1 diagram"
<span>{t('diagram.count', { count: 5 })}</span>  // "5 diagrams"
```

## Testing Translations

```typescript
// ✅ Good - Test with i18n
import { render, screen } from '@testing-library/react';
import { I18nextProvider } from 'react-i18next';
import i18n from 'i18next';

// Mock i18n for tests
i18n.init({
    lng: 'en',
    resources: {
        en: {
            common: {
                button: {
                    save: 'Save',
                },
            },
        },
    },
});

function renderWithI18n(component: React.ReactElement) {
    return render(
        <I18nextProvider i18n={i18n}>
            {component}
        </I18nextProvider>
    );
}

it('renders translated button', () => {
    renderWithI18n(<SaveButton />);
    expect(screen.getByText('Save')).toBeInTheDocument();
});
```

## Translation Keys in Code

### Avoid Hardcoded Strings

```typescript
// ❌ Bad - Hardcoded strings
export const Button: React.FC = () => {
    return <button>Save</button>;
};

// ✅ Good - Translated strings
export const Button: React.FC = () => {
    const { t } = useTranslation();
    return <button>{t('common.button.save')}</button>;
};

// ❌ Bad - Hardcoded error messages
throw new Error('Invalid input');

// ✅ Good - Translated error messages
throw new Error(t('errors.validation.invalid'));
```

## Missing Translations

```typescript
// ✅ Good - Handle missing translations
i18n.init({
    fallbackLng: 'en',
    saveMissing: true, // In development
    missingKeyHandler: (lng, ns, key) => {
        console.warn(`Missing translation: ${lng}.${ns}.${key}`);
    },
});
```

## Best Practices Summary

### Do's
- ✅ Use hierarchical, descriptive translation keys
- ✅ Organize translations by feature/domain
- ✅ Use useTranslation hook
- ✅ Support pluralization
- ✅ Provide context for translators
- ✅ Use Trans component for complex HTML
- ✅ Support RTL languages
- ✅ Format dates/numbers according to locale
- ✅ Lazy load translations
- ✅ Test translated components
- ✅ Use namespaces to organize translations
- ✅ Handle missing translations gracefully

### Don'ts
- ❌ Don't hardcode user-facing strings
- ❌ Don't use unclear translation keys (msg1, btn_1)
- ❌ Don't concatenate translated strings
- ❌ Don't put HTML in translation keys (use Trans)
- ❌ Don't forget to translate error messages
- ❌ Don't assume text direction (support RTL)
- ❌ Don't duplicate translation keys
- ❌ Don't forget to handle pluralization
- ❌ Don't use translation keys as default values
- ❌ Don't forget to provide fallback language
